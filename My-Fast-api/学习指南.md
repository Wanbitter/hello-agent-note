## 二、贯穿全程的三层认知模型

**这是整份指南的地基。** 任何时候搞不清"这行东西在哪写、在哪用"，就回到这张图：

```
① 你写的（Python）        httpx.get(url, headers={"Accept-Language": "fr"})
                                    ↓  库替你拼装
② 报文本体（MDN 展示的）   GET / HTTP/1.1
                          Host: developer.mozilla.org
                          Accept-Language: fr
                          ← 空行 → 体
                                    ↓  TCP / TLS 送出去
③ 网线上的字节            一样的内容，只是被 TCP 切成了段
```

| 报文里的行 | 谁生成的 | 客户端你写什么 | 服务端你怎么读 |
| --- | --- | --- | --- |
| `GET / HTTP/1.1` | 方法（你选的动词）+ 路径（URL 的 path）+ 版本 | `httpx.get("https://.../")` | `request.method` / `request.url.path` |
| `Host: developer.mozilla.org` | **域名自动填**，你从没写过它 | 同上，URL 里的域名 | `request.headers["host"]` |
| `Accept-Language: fr` | **只有这行是你手写的** | `headers={"Accept-Language": "fr"}` | `request.headers["accept-language"]` |

> 服务端那半边的文档：[FastAPI · 直接使用 Request](https://fastapi.tiangolo.com/zh/advanced/using-request-directly/)

**三条铁律**

1. **报文是证据，不是源码。** 你写代码是在*制造*证据，`curl -v` / 抓包是在*检验*证据。
2. **你永远不会手写 `GET / HTTP/1.1`**，除非你在写 HTTP 库本身。你只写第 ① 层。
3. **debug 时永远看成报文，不要盯着自己的 Python 代码。** FastAPI 报 `422` 时，答案不在你的 `@app.post` 里，在报文里。

> **一个必须知道的限制**：你只能对 `http://`（80 端口，明文）手写报文。`https://` 的报文被 TLS 加密，你往 socket 里写明文会被 TLS 层挡掉——那不是你写错了，是协议设计如此。

## 1.4 坑表（老教材 vs 实际）

| # | 老教材 / 常见说法 | 正确说法 | 什么时候会咬你 |
| --- | --- | --- | --- |
| 1 | "HTTP 是无连接的，处理完就断开" | 那是 HTTP/1.0；1.1 起 keep-alive **是默认值**。准确说法：协议不*规定*连接寿命 | 写 SSE 时以为连接会自己关 |
| 2 | "2xx 表示正在处理" | 2xx = **成功**，正在处理是 1xx；"收下了没做完"是 **202** | 拿 202 当成功的终态，永远等不到结果 |
| 3 | "无状态 = 每个事件独立处理" | 是**协议层不替你记**；服务器照样能处理有前后依赖的业务 | 以为 agent 天然能记住上下文 |
| 4 | "媒体独立"读不懂 | = **HTTP 是个信封，不管信里写什么**；靠 `Content-Type` 声明 | 以为 HTTP 只能传 JSON/HTML |
| 5 | 以为 `Host` 要自己手写 | 由 URL 域名**自动生成**（HTTP/1.1 强制要有） | 手写报文时漏了它 → 400 |
| 6 | 以为能手写 HTTPS 报文 | 明文会被 TLS 挡下，只能对 `http://` 手写 | 在 443 端口上调试半天 |
| 7 | PowerShell 里直接 `curl` | 可能是 `Invoke-WebRequest` 的别名，输出完全不同 | 对着假报文分析半天 |
| 8 | 中文输出乱码以为是 bug | PowerShell 默认 GBK 解码 UTF-8；先设 `$env:PYTHONIOENCODING='utf-8'` | 浪费一小时查"编码问题" |

## 2.2 实操 · 六关（在 `My-Fast-api\` 下演进 `main.py`）

> 规则：**每关只改一件事，改完必须能一句话说清"我改了什么、为什么"**。

**关 3 · 校验与 422**
- 给模型加约束（必填、长度、范围），然后**故意发一个不合法的请求**（比如缺必填字段）。
- 看服务器返回的 `422` 和错误详情长什么样。**这就是"报文里有答案"的现场。**
- 加 `response_model`，故意返回多一个字段，看它被怎么处理。
- 文档：[请求体 - 字段](https://fastapi.tiangolo.com/zh/tutorial/body-fields/) ｜ [响应模型](https://fastapi.tiangolo.com/zh/tutorial/response-model/) ｜ [严格的 Content-Type 检查](https://fastapi.tiangolo.com/zh/advanced/strict-content-type/)（进阶看）
- 过关：能说清"校验发生在我的函数执行**之前**还是之后"。

**关 4 · 状态码与错误**
- 让接口按条件返回 `201` / `404` / `409`；再用 `HTTPException` 抛一次。
- 对比"抛异常"和"返回错误 dict"两种做法，在 `/docs` 里的差别。
- 文档：[响应状态码](https://fastapi.tiangolo.com/zh/tutorial/response-status-code/) ｜ [处理错误](https://fastapi.tiangolo.com/zh/tutorial/handling-errors/) ｜ [额外的状态码](https://fastapi.tiangolo.com/zh/advanced/additional-status-codes/)
- 过关：能说出为什么**错误要用异常而不是返回值**。

**关 5 · `async def` 的坑（本阶段最重要）**
- 写两个接口：`async def` 里 `await asyncio.sleep(3)`，和 `async def` 里 `time.sleep(3)`。
- 各用**两个并发的 `curl.exe`** 同时打，掐表看总耗时。
- 文档：[并发 async / await](https://fastapi.tiangolo.com/zh/async/)
- 过关：能解释"为什么 `time.sleep` 那两个请求变成串行了"，并说出正确改法（`def` 或 `asyncio.to_thread`）。

**关 6 · CORS 实测**
- 加 `CORSMiddleware`，用一个简单 HTML 页面在浏览器里 fetch 你的接口。
- 先用 `curl.exe -v -X OPTIONS` 手动发一次预检，看返回了哪些 `Access-Control-*` 头。
- 文档：[CORS](https://fastapi.tiangolo.com/zh/tutorial/cors/) ｜ [MDN · CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/CORS)

# 阶段三 · 回 Agent

**目标**：把 HTTP 和 FastAPI 学到的，接回你的 agent 主线。这一步**不是新知识，是缝合**。
**触发时机**：阶段二过关之后，或者书读到第 13 章需要跑通后端时。

## 3.1 核心矛盾：无状态的 HTTP vs 有状态的 Agent

Agent 天然有状态（会话历史、记忆、工具中间结果），HTTP **协议层不记你**。缝合法只有一条主线：

```
客户端每次带上 session_id
        ↓
服务端用它去【某个地方】捞出上下文
        ↓
把上下文喂给 agent → 跑 → 把新状态写回【那个地方】
```

**关键设计问题（这才是这一阶段的真考点）**：那个"某个地方"放哪？

| 方案 | 优点 | 代价 | 什么时候用 |
| --- | --- | --- | --- |
| 内存字典 | 三行代码 | 多 worker / 重启就丢 | 本地实验 |
| SQLite / 文件 | 能持久化 | 并发写要小心 | 单机小项目（第 8 章 `memory.db` 就是） |
| Redis | 快、能过期 | 多一个服务 | 多 worker 部署 |
| 向量库 | 能语义召回 | 召回不一定准 | 长期记忆（第 8 章 Qdrant） |

> 这一节直接接上你 `8-0` 目录里那套记忆系统——**FastAPI 只是把记忆系统暴露成 HTTP 接口的那层壳**。

## 3.2 SSE 流式（书第 14 章的核心）

**这里是新旧写法分岔的地方，别照着书手搓：**

| 写法 | 长什么样 | 用途 |
| --- | --- | --- |
| **老写法**（书第 14 章 643–645 页） | `StreamingResponse(gen(), media_type="text/event-stream")` + 自己拼 `data: {...}\n\n` | **理解原理用它**：你能看清每个字节是谁写的 |
| **新写法**（FastAPI ≥ 0.135.0） | `@app.get("/x", response_class=EventSourceResponse)` + 函数里 `yield` 对象 | **真正写项目用它**：转义、`id`、`retry`、`Last-Event-ID` 续传都由框架管 |

你的 0.136.3 **支持新写法**：

```python
from fastapi.sse import EventSourceResponse     # 注意是这个模块
from collections.abc import AsyncIterable

@app.get("/items/stream", response_class=EventSourceResponse)
async def sse_items() -> AsyncIterable[Item]:
    for item in items:
        yield item        # 也可以 yield ServerSentEvent(data=..., event=..., id=...)
```

- 文档：[FastAPI · 服务器发送事件（SSE）](https://fastapi.tiangolo.com/zh/tutorial/server-sent-events/)（含 `ServerSentEvent`、原始数据、`Last-Event-ID` 恢复、用 POST 发 SSE）
- 参考手册：[Server-Sent Events · EventSourceResponse](https://fastapi.tiangolo.com/zh/reference/sse/)
- 相关页：[流式传输 JSON Lines](https://fastapi.tiangolo.com/zh/tutorial/stream-json-lines/)（**不是** SSE，别混）｜ [流式数据](https://fastapi.tiangolo.com/zh/advanced/stream-data/)（二进制流）｜ [自定义响应 - 流](https://fastapi.tiangolo.com/zh/advanced/custom-response/)
- 客户端侧：[MDN · 使用服务器发送事件](https://developer.mozilla.org/zh-CN/docs/Web/API/Server-sent_events/Using_server-sent_events)（浏览器 `EventSource`）

**三个必须记住的点**：
1. **状态码在第一个字节前定死**，所以流里的错误只能当消息发（老写法尤其要注意，见坑表 #6）。
2. 头和体之间那个 **空行** 之后，响应就"已经开始"了。
3. SSE 是**长连接**——回到阶段一的坑 #1，这里就是它咬人的地方。

## 3.3 工具服务化 / MCP（预告）

回到第二节那张三层图：**MCP 就是"把工具调用写成 HTTP 报文"的一层约定**（JSON-RPC + SSE 传输）。你前面学的 `Content-Type`、状态码、长连接、`101 Switching Protocols`，在这里全部复用一遍。到那时你会发现没有新东西。

## 3.4 工程细节（agent 特有的麻烦）

| 问题 | 为什么 agent 特别严重 | 方向 | 文档 |
| --- | --- | --- | --- |
| 超时 | 一次 agent 跑几十秒，HTTP 客户端默认超时全都不够 | 显式设超时；长任务改成 202 + 轮询 | — |
| 长任务 | 同步等结果会占满连接 | "提交 → 返回任务号 → 轮询/SSE 推进度" | [后台任务](https://fastapi.tiangolo.com/zh/tutorial/background-tasks/) |
| 并发 | 同步阻塞会把服务卡死 | 阶段二关 5 | [并发 async / await](https://fastapi.tiangolo.com/zh/async/) |
| 重试 | 重试可能**重复执行工具**（花钱、有副作用） | 区分幂等与非幂等操作 | — |
| 成本 | 一个请求可能调十几次 LLM | 日志 + 限流 | — |
| 多进程 | 内存里的会话状态在 worker 之间不共享 | 状态外置（见 3.1） | [Workers](https://fastapi.tiangolo.com/zh/deployment/server-workers/) |
