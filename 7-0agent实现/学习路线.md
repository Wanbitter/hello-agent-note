## 一、路 B 这一章到底学什么

一句话：**把框架当积木用一遍，并用"继承"这一个动作学会框架的接口契约。**

| 你在做什么 | 学到的东西 |
| --- | --- |
| 继承 `HelloAgentsLLM` 加 provider | 一个库要怎么设计，才能让用户"不改源码就能扩展" |
| 读 `Message` / `Config` / `Agent` 基类 | 数据校验、配置分层、抽象基类各自解决什么问题 |
| 写自己的工具（计算器 / 搜索 / 工具链 / 异步执行） | 工具系统的两条注册路径、异常边界、安全求值 |
| 继承重写四种 Agent 范式 | 第四章的散装逻辑，放进统一接口后长什么样 |

路 B 的产物是**一个用框架搭起来的项目**（`my_*.py` 一族），不是重造框架。
好处是快、能立刻用；代价是框架内部实现不会亲手写一遍——那部分靠"读源码 + 预测-验证"补。

## 三、先知道就不踩的坑

| # | 坑 | 正确姿势 |
| --- | --- | --- |
| 1 | 在 `7-0agent实现/` 下自己建一个 `hello_agents/` 目录 | **千万别**。当前目录优先于 site-packages，你那份会盖掉 pip 版，路 B 直接崩 |
| 2 | 以为 `think()` 返回字符串 | 0.1.1 里 `think()` 是**流式生成器**；要整段文本用 `invoke()`。7.4 的 ReActAgent 内部用的就是 `invoke` |
| 3 | 奇怪"为什么 demo 里的 `agent.add_tool(...)` 被注释掉了" | 因为 0.1.1 的 `SimpleAgent` **不支持工具**，只支持 `name/llm/system_prompt/config`。7.4.1 让你自己写 `MySimpleAgent` 补上这块 |
| 4 | `_auto_detect_provider` 的优先级记反 | 顺序是：**特定 provider 的环境变量 > key 格式 > base_url > 默认 auto**。你 `.env` 只有 `LLM_*`，所以是 `api.deepseek.com` 这个 base_url 把它判成 deepseek |
| 5 | 子类 `super().__init__(provider="auto")` 之后，`inst.provider` 不是 "deepseek" | 正常。`"auto"` 是真值，父类就不会再自动检测了——但 `_resolve_credentials("auto")` 照样从 `LLM_*` 取到凭据，**能用**。别把"标签"当"功能"验 |
| 6 | `ToolRegistry` 给工具传参想当然 | Tool 对象统一收到 `{"input": 文本}`；裸函数直接收到字符串 |
| 7 | 工具里抛异常把 Agent 主循环炸死 | 框架会 catch 成 `"错误：..."` 字符串，这是 Observation 的来源；你自己写工具时也要守这个边界 |
| 8 | 用 `eval` 写计算器 | 用 `ast.parse` + 节点白名单 |
| 9 | 以为要写 `FunctionCallAgent` | 7.4.5 只是介绍，**0.1.1 里没有它**（0.2.8 之后才加），跳过 |
| 10 | 终端里中文输出变乱码 | 跑之前 `$env:PYTHONIOENCODING='utf-8'`（这次我跑 demo 就撞上了，功能正常，只是显示乱） |
| 11 | 照 7.2.2 在 Windows 上 `pip install vllm` | 官方只发 Linux 轮子（社区还得自己重建 Windows 版），装上也是缺 `_C` 编译内核的残废包：`import vllm` 直接 `ModuleNotFoundError`，还会顺带把 venv 拉进 100+ 个依赖。**本地模型走 Ollama**，vllm 要用就在 WSL2 里装 |
